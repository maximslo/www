## Design Decisions
### ProseMirror over raw HTML, so one authored doc could feed two outputs that can't drift apart.
Editors were pasting the same answer twice, as HTML and the schema, with nothing keeping the copies in sync. ProseMirror gave us a structured document instead, and we built a serializer on top that read one doc into both the FAQ accordion and the FAQPage JSON-LD.

## Exploring Form Factors
### Insights on structuring recipe schema for AI discovery
#### One typed entity per concern, not one blob


<CodeWindow title="respond.ts" variant="light">

```ts
<!-- Block 1: the recipe facts -->
<script type="application/ld+json">
{
  "@context": "https://schema.org",
  "@type": "Recipe",
  "name": "Quiche Lorraine"
}
</script>

<!-- Block 2: the publisher trust graph, kept separate -->
<script type="application/ld+json">
{
  "@context": "https://schema.org",
  "@type": "Organization",
  "name": "NYT Cooking"
}
</script>
```

</CodeWindow>

#### Give every step/claim a stable anchor
If an AI system wants to cite "step 4," it needs a URL that resolves to just step 4, not the whole page. Pair each HowToStep with a deep link into the DOM.

<CodeWindow title="respond.ts" variant="light">

```ts
<script type="application/ld+json">
{
  "@type": "Recipe",
  "recipeInstructions": [
    {
      "@type": "HowToStep",
      "text": "Heat the oven to 400 degrees.",
      "url": "https://example.com/recipes/quiche-lorraine#recipe-step-1"
    },
    {
      "@type": "HowToStep",
      "text": "Cook the bacon until crisp.",
      "url": "https://example.com/recipes/quiche-lorraine#recipe-step-2"
    }
  ]
}
</script>

<!-- matching anchor in the actual page markup -->
<li id="recipe-step-2">
  <p>Cook the bacon until crisp.</p>
</li>
```

</CodeWindow>


#### Resolve identity, don't just name it
A bare string like "author": "Claire Saffitz" is unresolvable. Nest it as a Person entity with a sameAs/url back to a canonical bio page. This turns a fact into a fact an LLM can verify.
<CodeWindow title="respond.ts" variant="light">

```ts
<script type="application/ld+json">
{
  "@type": "Recipe",
  "author": {
    "@type": "Person",
    "@id": "urn:example:person:claire-saffitz",
    "name": "Claire Saffitz",
    "url": "https://example.com/by/claire-saffitz",
    "sameAs": "https://en.wikipedia.org/wiki/Claire-Saffitz"
  }
}
</script>
```

</CodeWindow>

#### FAQ content earns its own schema
Question-form headers with self-contained answers are the single highest-yield format for verbatim AI citation. If Q&A content is buried in prose paragraphs, pull it out into a dedicated FAQPage block.
<CodeWindow title="respond.ts" variant="light">

```ts
<script type="application/ld+json">
{
  "@context": "https://schema.org",
  "@type": "FAQPage",
  "mainEntity": [
    {
      "@type": "Question",
      "name": "What is quiche?",
      "acceptedAnswer": {
        "@type": "Answer",
        "text": "A savory custard tart in a buttery crust, traditionally known as pâte brisée."
      }
    },
    {
      "@type": "Question",
      "name": "Can quiche be made ahead of time?",
      "acceptedAnswer": {
        "@type": "Answer",
        "text": "Yes — the dough can be prepped up to 3 days ahead, or the crust par-baked a day in advance."
      }
    }
  ]
}
</script>
```

</CodeWindow>
