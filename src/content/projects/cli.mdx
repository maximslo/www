## Research
### Where web search API’s go wrong

Imagine you are developer looking to ground your agent with fresh worldview context.

<img src="/projects/terminal-research.png" width="1600" height="1200" alt="Comparison of web search tools answering a commodity news question correctly versus hallucinating on an exclusive Washington Post investigation" class="outlined" />

For general use, currently available tools work but don’t guarantee live or high-quality links. They pull from cached or indexed sources that haven’t been revalidated, which can lead to 404s or dead pages.

## Pain points
### 1) Most critical content is paywalled
Subscription sources like The Washington Post block these tools entirely, making investigational outcomes and critical reporting unreachable.

In the worst cases, tools silently degraded to older, lower-quality sources that make it confidently wrong.

### 2) The news cycle isn't generic web text.
These tools aren't built for news, they're structurally wrong. Even if The Washington Post allowed agent scrapers, we found their tooling wasn't built to handle reporting.

<div class="cols">
  <div>
    <h4>Attribution gets lost</h4>
    <p>Reporting and op-ed's are weighed the same. Retrieval returns passage chunks via embedding similarity.</p>
  </div>
  <div>
    <h4>Change is invisible, corrections don't carry</h4>
    <p>To check story changes, an agent has to re search and compare everything itself. Reports and op-ed's are weighed the same.</p>
  </div>
  <div>
    <h4>Usage rights are untraceable</h4>
    <p>To check if a story changed, an agent has to search again and compare everything itself.</p>
  </div>
</div>

## Why CLI?
<div class="cols">
  <div>
    <h4>Token efficiency</h4>
    <p>Agents run shell commands natively, output pipes into any workflow.</p>
  </div>
  <div>
    <h4>Per-call pricing</h4>
    <p>Every command is a billable, receipt-stamped event.</p>
  </div>
  <div>
    <h4>Easy setup</h4>
    <p>We found a CLI and skill fit easily in developers current workflows. A setup command can install as an agent skill. No protocol integration.</p>
  </div>
</div>

#### Two audiences, one code path
I used payload with two views, so the JSON `--agent` gets and the table a `--human` gets never drift out of sync:

<CodeWindow title="respond.ts" variant="light">

```ts
function respond<T extends object>(payload: T, toTable: (p: T) => string) {
  const machineMode = flags.agent || (!flags.human && !process.stdout.isTTY);

  if (machineMode) {
    return JSON.stringify({ ...payload, meta: buildMeta(payload) }, null, 2);
  }
  return toTable(payload);
}
```

</CodeWindow>

## Core Flows

<div class="cols">
  <div>
    <h4>`wapo story`</h4>
    <p>Resolves a topic to a thread ID **once**.</p>
  </div>
  <div>

    <p>Answers questions against that thread. From then on, monitoring is a cheap `--since` cursor check.</p>

    <p>Spot-checks claims the agent already holds in context.</p>

## Design Decisions
#### The atomic unit is the claim, not the headline

What is the smallest independently-citable thing? I explored options and took inspiration from how Context7 chunks docs so every unit carries its own provenance.

<img src="/projects/atomic-unit.png" width="1600" height="1200" alt="Four candidate atomic units compared side by side — headline, article, embedding chunk, and claim — showing what an agent receives for each and why the claim is the only one that resolves cleanly" class="outlined" />
